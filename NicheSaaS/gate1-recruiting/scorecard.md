# Gate 1 scorecard

Roll up the twelve capture sheets here. This produces the verdict.

**Pass:** ≥8 of 12 independently name writeup time or deficiency-to-quote
conversion in their top three pains **and** can state a dollar figure.

**Fail:** switch to Candidate 2 (due-diligence report production) and re-run.

The volunteered count is not part of the threshold but read it anyway. Eight
counts made up mostly of extracted pain is a materially weaker result than eight
volunteered, and it predicts trouble at Gate 3 — pain you had to dig for is pain
they can live with.

## Sample quality

Check this before trusting the verdict. A passing score from a skewed sample is
worse than a failing one from a clean sample, because it is actionable and wrong.

| Check | Target | Actual | OK |
|---|---|---|---|
| Owners / principals | ≥4 | | |
| Ops / service managers | ≥4 | | |
| Shops under 10 techs | ≥3 | | |
| Shops over 25 techs | ≥3 | | |
| Distinct states | ≥4 | | |
| From a single referral cluster | ≤5 | | |

If the referral chain produced more than five of the twelve from one cluster,
they likely share an operating model and the result generalises to nothing.
Source three more from a cold channel before calling it.

Gate 1 failure — revisit seat-based versus per-report before Gate 3.

## Flip trigger

| | Count |
|---|---|
| Read as device-hostile | / 12 |
| Tried a mobile tool and abandoned it | / 12 |

**If ≥6 of 12 are device-hostile, switch to Candidate 2 regardless of the pain
scores.** The capture premise is dead and every feature in
[`../03-product-concept.md`](../03-product-concept.md) depends on it.
